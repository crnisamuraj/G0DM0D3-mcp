🧗 Challenges & Resolutions ▾

Update

Official mcp SDK is now required

The constrained-environment workarounds (manual MCP fallback server and standalone test runner) have been removed from the codebase.

Resolution

mcp 1.x is listed as a required dependency in pyproject.toml. Both stdio and HTTP/SSE transports use the official SDK.

Challenge

Virtualenv Python resolved to an AppImage

Creating a venv produced a python binary linked to the OpenCode AppImage, which reset sys.path and ignored the venv site-packages, making installed packages unreachable.

Resolution

Ran validation with the system interpreter and PYTHONPATH=src instead of relying on venv-isolated execution. This allowed imports and tests to pass while keeping the build self-contained.

Challenge

Chat method routing was mirrored from URL paths

Original implementation tried to resolve the client method from the last path segment ("completions"), which does not exist on Godmod3Client.

Resolution

Changed _send_chat to take an explicit client method name (chat_completions, ultraplinian_completions, consortium_completions) so each mode calls the correct endpoint.

Challenge

Test runner updated to pytest

The standalone runner (tests/run_tests.py) and the manual-server test were removed along with the manual fallback.

Resolution

Tests now run exclusively with pytest tests/test_tools.py. The remaining 6 utility tests pass and remain pytest-collectible via pytest-asyncio.

🚀 How to Use ▾

1. Start G0DM0D3 API

$ docker compose up -d --build

2. Install the bridge

$ pip install -e .

3. Run

$ python -m godmod3_mcp.server # stdio
$ python -m godmod3_mcp.server --transport http --port 3001

4. Connect to Odysseus / Hermes

Copy the appropriate skill directory and register the MCP server using the README instructions.
